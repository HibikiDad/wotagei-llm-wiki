# 反思

依據的紀錄：[wiki/log.md](../wiki/log.md)（20 筆）、[checks/](../checks/) 裡 23 份自動 lint、5 份 check_slides、
[LLM lint](../checks/lint-llm-20261123.md)、[事實查核](../checks/slides-factcheck-20261123.md)、[渲染檢查](../checks/slides-render-20261123.md)。

## 1. 哪個節點最常失敗？

**「寫入 wiki」這個節點**（Ingest 第 4 步），它有兩種失敗方式：

| 失敗方式 | 次數 | 什麼時候被抓到 | 代價 |
|---|---|---|---|
| **A. 用了不採用寫法**（lint E5） | 23 次 lint 裡 3 次 FAIL，**全部都是 E5**：S01「地下芸」×3、S03「秋葉原系」×3、S06「耶太嘎」「愛孥語」 | 寫完馬上被 `lint_wiki.py` 抓到 | 低：修一行、重跑一次 |
| **B. 使用者的修正沒有擴散到所有頁面** | 至少 6 處 | 晚好幾步才被抓到（見下表） | 高：錯的說法已經被其他頁和投影片大綱引用 |

B 的細節：

| 過時的說法 | 推翻它的討論 | 被誰抓到 | 晚了幾步 |
|---|---|---|---|
| glowstick「台灣現場以 LED 為主」 | S08 討論（只限演唱會） | LLM Lint | 1 次 ingest |
| taiwan 頁的同一句 | 同上 | S10 ingest 時順手發現（**LLM Lint 漏掉**） | 2 次 ingest |
| glowstick 的錯誤引用「{Bb}」 | — | S10 ingest 時順手發現（**自動 lint 抓不到**，因為它不是連結） | 2 次 ingest |
| overview「厄介（麻煩的人）」「LED 為主」 | S09、S08 討論 | 寫簡報前重讀 overview（自動 lint、LLM lint 都漏掉） | 進入 Slides Graph 才發現 |
| yetta-tiger「台灣喊家虎＝厄介」 | S10 討論（看場合） | 簡報事實查核 | 投影片都寫好了才發現 |
| wotagei 沒寫進 S10b 的 FAQ | — | 簡報事實查核 | 同上 |

A 的次數比較好數，但 B 才是真正的問題：A 每次都在同一步被攔下，B 卻一路漏到簡報。
共同原因都是「寫的時候沒有回頭比對既有的東西」：
- A 是沒比對 glossary：引述來源時直接照抄原文的寫法。
- B 是沒比對其他頁：只改了當次 ingest 碰到的頁面。

## 2. 把檢查往前移到哪裡？

| 問題 | 原本在哪裡被抓到 | 往前移到 | 怎麼做 |
|---|---|---|---|
| A 用語 | 第 5 步 lint（寫完之後） | **第 3 步 🧑 討論** | 討論時就把「新出現的用語」逐一對照 glossary 的不採用寫法欄，當場決定標準寫法，寫入時直接用標準寫法 |
| B 修正沒擴散 | LLM lint、事實查核（好幾步之後） | **第 3 步討論＋第 4 步寫入** | 使用者的修正如果**推翻**了既有說法：<br>1. 討論時就列出「這會推翻哪句舊說法」<br>2. 寫入時用 `grep` 找出全 wiki 所有出現的地方一起改，並把 grep 結果記到 log |
| overview 落後 | 寫簡報前重讀 | 第 4 步寫入 | overview 是新手入口，最容易殘留舊說法 → 每次討論修正推翻既有說法時，固定檢查 overview |

這三條已經寫回 schema（[CLAUDE.md §3.1](../CLAUDE.md) 第 3、4 步），下一次 ingest 就會照做。

Slides Graph 裡也有一個「往前移」的例子，在這次執行中就做了：
- check_slides（幾秒鐘）放在 LLM 事實查核（要讀 33 張）之前，先濾掉機械性錯誤。
- 寫 check_slides 時先用故意埋錯的副本做反向測試，確認 4 類錯誤都抓得到，才拿來檢查真的簡報。
  反向測試也順便抓到工具本身的 bug：遇到相對路徑參數就會失敗。

## 3. 每個檢查抓得到、抓不到什麼

| 檢查 | 抓到 | 抓不到（要靠下一關） |
|---|---|---|
| `lint_wiki.py` | 斷鏈、缺出處、E5 用語 | 不是連結格式的錯誤引用（`{Bb}`）、內容過時 |
| LLM Lint | 跨頁矛盾、過時說法、資料缺口 | 會漏（taiwan 頁那句就漏了）—— LLM 檢查不是窮舉 |
| `check_slides.py` | 缺出處、出處不存在、用語、圖片、未 ingest 的影片 | 陳述**實際**來自哪一頁（第 29 張的 AKB48 出處不完整） |
| LLM 事實查核 | 投影片與 wiki 對不上、wiki 本身過時 | 版面 |
| 渲染：腳本量測 | 溢出、裁切、圖片載入 | 被別的元素蓋住、影片被上傳者限制外部播放 |
| 渲染：截圖 | 遮擋、影片能不能播 | —（但修完要重新截圖：這次的修正就造成了新的版面問題） |

結論：**每種檢查都有盲點，所以要串起來，而且要讓便宜的先跑**。
確定性的腳本負責「全面、快速」，LLM 和截圖負責「看懂內容與畫面」。

## 4. 工作流程有沒有改變？

有。這次執行中改了這些地方：

1. **新增 S00「使用者討論紀錄」**（16:10 schema 變更）：
   - S01 討論時，使用者提出和維基百科不同的三分法（一般應援／地下藝／表演藝）。
   - 這種圈內知識沒有書面來源，原本的流程無處可放，所以新增 S00，並規定和書面來源衝突時兩邊並列。
   - 之後每次 ingest 都有使用者修正記到 S00，例如 S06 討論**推翻了** S05 討論時「打call＝一般應援」的結論。
     因為留有紀錄，call.md 可以保留「⚠️ 說法修正」，而不是悄悄改掉。
2. **lint E5 排除全形括號內的原文註記**：S01 第一次 FAIL 後發現，括號註記本來就要寫原文，規則太嚴。
3. **無字幕影片剔除**：
   - 其他 18 支是在列清單檢查字幕時就篩掉的（[backlog](../raw/backlog.md)），但 S06a 是到 ingest 抓取時才發現沒有字幕 → 剔除。
     教訓：字幕檢查要在**規劃來源時**就對每一支影片做，不要等到抓取。
   - 剔除後來源要重新編號：kknews 插入成 S07，祈哥順延成 S08。之後就規定編號一旦給定就不再變動，空號保留給預定的來源（S09 留給厄介）。
4. **大綱審核把流程倒回 Ingest**：
   - 大綱寫出來後才發現台灣圈團體、比賽、厄介的資料不夠，回頭 ingest 了 S09～S11 才通過審核。
   - 這證明 Slides Graph 的「wiki 缺資料 → 回 Ingest」這條邊是必要的。
5. **渲染檢查從「看截圖」變成「腳本量測＋截圖」**：
   - 33 張都用 DOM 量測溢出，截圖負責看遮擋。
   - 修正後再回到 check_slides 和重新截圖。
6. **log 的時間改用 `date` 查**：
   - 前後兩次把 log 的時間寫成估計值，其中一次（17:45）甚至比當時的時鐘還晚。
   - 兩次都改成對應 commit 的實際時間。現在每筆 log 寫之前都先跑 `date`。
   - 這是流程問題，不是內容問題，但檢查紀錄的時間錯了，紀錄就不可信。
